## 沒有列進來但你可能會問的三件事

**「付款流程測過了嗎？」** 單元測試層面測透了（簽章驗證、竄改、重放、金鑰輪替、去重、測試模式隔離、金額不進分析、16 個測試）。**真實刷卡沒測**，因為沒有 Stripe 憑證，而規則寫明不得在缺憑證時製造假的付款成功。測試卡的逐步清單在 `STRIPE_SETUP.md` 第四節。

**「purge 會不會誤刪？」** 不會，它預設 dry run（`PURGE_ENABLED` 未設就只計數不寫入），而且 `?dry=1` 永遠強制預覽。要真的開始刪，設 `PURGE_ENABLED=true`。建議先用 dry run 跑一次看它報幾筆，再開。

**「舊的 offer id 會不會壞掉？」** 不會。十個舊 offer 保留在 `OFFER_IDS` 裡，所以歷史 `scores` 列照樣解析；它們只是永遠不會出現在任何公開頁面。報告頁遇到舊分類會自動退回現行的兩檔目錄，有測試守著。
